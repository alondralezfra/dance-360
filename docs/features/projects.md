# Projects (home, workspace, saving)

*Code: `src/features/projects/`, `src/persistence/`, `src/store/`. Plan: §5.1, §5.5.*

## What it does today

- **Home** (`/`): lists projects, most recently edited first; create (`+ New project`, opens it straight away) and delete (asks first). Empty state when there are none. Each project has an **Export** button and the page has **Import project** (see below).
- **Backups.** *Export* saves a `.dance360.json` file of the project (named "Spring Show 2026-11-10.dance360.json") to the browser's downloads: the whole project (formations, dancers, parts, sections, assignments, links, tempo, stage) and the song's name, length and fingerprint, **never the audio**. *Import project* reads such a file and adds it as a **new project** ("Spring Show (imported)") and opens it; it never replaces or changes an existing project, so importing twice makes two copies. A project saved by an older version of the app is upgraded on the way in; a file from a newer version is refused with "update the app", and a file that is not a backup, is too large (over 5 MB) or is damaged says so in a dismissible alert and adds nothing. A song attached to the imported project shows the usual "not on this device, choose the file again" notice. After a project is created or imported the browser is asked to keep this site's data (persistent storage), so it is less likely to be cleared.
- **When a screen crashes** an error screen replaces the blank page: "Something went wrong. Your work is saved automatically as you go...", with *Reload*, *Back to your projects* and, if a project was open, *Download this project* (the same backup file), plus the technical message in a disclosure. Errors in event handlers or background work are not caught (they go to the console).
- **Workspace** (`/projects/:id`): loads the project named in the URL, then shows its header (breadcrumb `Dance 360 › <project name>`, editable project name, **tabs** (Stage, Cast & Parts, Song, Resources; the active one is marked `aria-current`), save status, theme toggle) and the current screen. On wide screens the tabs share the header row to leave more room for the screen; on phones they take their own row beside Undo/Redo, where the row **scrolls sideways** when the tabs do not all fit (no scrollbar is drawn; the open tab is always scrolled fully into view, also when you open its address directly, and the next tab peeks in at the edge as a hint). [decisions/0027](../decisions/0027-resources-links.md) `/projects/:id` redirects to `/stage`. Adding a screen = a route in `router.tsx` plus an entry in `tabs` in `ProjectWorkspace.tsx`.
- **Undo / Redo**: two buttons in the header (disabled when there is nothing to do) and Ctrl/Cmd+Z, Ctrl/Cmd+Shift+Z / Ctrl+Y undo and redo the last edit anywhere in the project: dots, formations, dancers, parts, sections, assignments, names. Typing in a name box is one step. The last 100 steps are kept for this session; opening another project or reloading starts clean. In a text box the keys undo the text instead. Undo results are autosaved like any edit.
- **Loading states**: "Loading…" while opening; a friendly message and a link back for a project that doesn't exist or was saved by a newer version of the app. Unknown URLs show a not-found page.
- **Saving**: every change is autosaved ~0.4 s later; the header shows *Saving…* / *Saved* / *Couldn't save*. Pending changes are saved immediately when you switch projects or hide/close the tab. Loading a project doesn't trigger a save.
- **Storage**: currently the browser's `localStorage` (this device only). Each project is stored with a data-version number so older saves are upgraded when opened, plus bookkeeping for future cloud sync (kept beside the project, not in it). Deleting a project removes it immediately (and clears its song file from the device if no other project uses it); once cloud sync exists, a synced project is kept as a hidden tombstone until the cloud is told.
- **One-time import**: the original prototype kept a single project under its own key; the first time the home screen loads it is moved into a real project and the old copy removed (only after the new one is written; unreadable old data is left untouched).
- **Theme**: light/dark toggle on both screens, remembered, defaulting to the system preference.
